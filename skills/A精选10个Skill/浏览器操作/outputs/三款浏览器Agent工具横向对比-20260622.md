# 三款浏览器 Agent 开源工具横向对比

> 对比对象：`skills/A精选10个Skill/浏览器操作/` 目录下的三款工具  
> 生成日期：2026-06-22

## 一、工具概览

| 维度 | Vercel **agent-browser** | 微软 **playwright-cli** | 阿里 **Page Agent** |
|------|--------------------------|-------------------------|---------------------|
| 仓库 | vercel-labs/agent-browser | microsoft/playwright-cli | alibaba/page-agent |
| 定位 | AI Agent 专用浏览器自动化 CLI | Coding Agent 专用、省 Token 的 Playwright CLI | 页面内嵌 GUI Agent / 产品 Copilot |
| 运行位置 | 本地/云端 CLI 进程（Rust daemon + CDP） | 本地 CLI 进程（Playwright 引擎） | **浏览器页面内** JavaScript |
| 依赖 | Chrome/Chromium（CDP），**不依赖 Playwright** | Node 18+、Playwright 浏览器 | 仅需 LLM API，无头浏览器/插件非必需 |
| 与 Agent 集成 | CLI + Skill + 可选 MCP | CLI + Skill（`playwright-cli install --skills`） | JS SDK + 可选 Chrome 扩展 + MCP Beta |
| 页面理解方式 | Accessibility Tree + `@eN` 元素引用 | Snapshot + 元素 ref | 纯文本 DOM 操作（**无截图、无多模态**） |
| 自然语言控制 | 有 `agent-browser chat`（内置 AI chat） | 无内置 NL，靠外层 Coding Agent 写命令 | **核心能力**：`agent.execute('点击登录')` |
| 典型用户 | Cursor/Claude Code 等通用 AI Agent | 同上，尤其强调与代码库共存的 Coding Agent | **SaaS 产品方**、前端开发者 |

## 二、架构差异（决定「该用哪个」）

```
┌─────────────────────────────────────────────────────────────────┐
│  外部 AI Agent（Cursor / Claude Code / 自研 Agent）              │
└────────────┬──────────────────────────────┬─────────────────────┘
             │ CLI 命令                      │ MCP / 扩展
             ▼                              ▼
   ┌──────────────────┐            ┌──────────────────┐
   │ agent-browser    │            │ playwright-cli   │
   │ (Rust + CDP)     │            │ (Playwright)     │
   └────────┬─────────┘            └────────┬─────────┘
            │ 控制任意网站/桌面 Electron       │ 控制任意网站
            ▼                              ▼
   ┌─────────────────────────────────────────────────────┐
   │              浏览器 / 无头 Chromium                   │
   └─────────────────────────────────────────────────────┘

   ┌─────────────────────────────────────────────────────┐
   │  Page Agent — 运行在「你自己的网页」内部              │
   │  <script> / npm import → 直接操作当前 DOM            │
   └─────────────────────────────────────────────────────┘
```

**关键分界**：
- **agent-browser / playwright-cli**：Agent **从外部**操控浏览器，适合自动化测试、爬虫、跨站任务、买机票等「Agent 替你上网」。
- **Page Agent**：Agent **住在页面里**，适合「给你的产品加 AI 副驾驶」，用户在自己产品内用自然语言操作。

## 三、能力细项对比

| 能力 | agent-browser | playwright-cli | Page Agent |
|------|:-------------:|:--------------:|:----------:|
| 跨站/任意 URL 自动化 | ✅ | ✅ | ❌（仅当前页/扩展跨标签） |
| Token 效率（CLI 省上下文） | ✅ 高（Rust CLI + 精简 snapshot） | ✅ 高（官方强调 vs MCP） | N/A（产品内嵌，不走 Agent 上下文） |
| 冷启动 / 性能 | ✅ 最优（Rust daemon，benchmark 领先） | 中等（Node + Playwright） | 轻（页面 JS，无额外进程） |
| 会话 / Cookie 持久化 | ✅ profiles、auth vault | ✅ session + `--persistent` | 随浏览器自然持久 |
| 可视化监控面板 | ✅ dashboard :4848 | ✅ `playwright-cli show` | Demo / 扩展 UI |
| Electron 桌面应用自动化 | ✅ 专用 skill | 有限 | ❌ |
| React 调试 / Web Vitals | ✅ 内置 | 需自行 eval | ❌ |
| 云浏览器 / Sandbox | ✅ Vercel Sandbox、AWS AgentCore | 需自建 | ❌ |
| 给终端用户用的 Copilot | ❌ | ❌ | ✅ **核心场景** |
| 无障碍 / 语音驱动页面 | 间接 | 间接 | ✅ 官方强调 |
| 与 Playwright 测试生态互通 | ❌ 独立栈 | ✅ 原生 | ❌ |
| 内置 NL 浏览器控制 | ✅ `chat` 子命令 | ❌ | ✅ `execute()` |

## 四、场景选型指南

### 选 **Vercel agent-browser** 当：

1. **通用 AI Agent 的默认浏览器工具** — Cursor/Claude Code 里「帮我打开网站、填表、截图、抓数据」
2. **复杂跨站流程** — 如文件夹名所示「成功买机票」：登录、选航班、支付等多步外部网站操作
3. **要极致 CLI 性能** — Rust 原生、冷启动快、batch 多命令、无 Playwright 依赖
4. **Electron 桌面应用** — VS Code、Slack、Figma 等（有专用 skill）
5. **探索性测试 / Dogfooding / QA** — snapshot diff、annotated screenshot、React 组件树
6. **云/沙箱部署** — Vercel Sandbox microVM、AWS Bedrock AgentCore

### 选 **微软 playwright-cli** 当：

1. **团队已在 Playwright 生态** — 测试、CI、现有 `@playwright/test` 项目，CLI 与测试栈一致
2. **Coding Agent 与代码库并行** — 官方定位：在有限上下文里同时写代码、跑测试、点浏览器，CLI 比 MCP 更省 Token
3. **需要 Playwright 特有能力** — 设备模拟、trace、与 Playwright Test 报告集成等
4. **多 Session 并行** — `-s=projectA` 分项目隔离浏览器，`PLAYWRIGHT_CLI_SESSION` 环境变量
5. **人工介入监控** — `playwright-cli show` 网格视图 + 远程接管，适合观察 Agent 后台跑浏览器

> 同目录下的 `playwright-skill-main` 是社区版「让 Claude 现场写 Playwright 脚本」，适合**一次性复杂定制自动化**，不是 Microsoft 官方 CLI；与 `playwright-cli` 是互补关系。

### 选 **阿里 Page Agent** 当：

1. **SaaS 产品内嵌 AI Copilot** — ERP/CRM/管理后台，用户说「帮我把这单审批通过」
2. **智能表单 / 多步 UI 向导** — 20 次点击变一句话，**无需改后端**
3. **无障碍增强** — 自然语言/语音操作自有 Web 应用
4. **只要文本 LLM** — 基于 DOM 文本，不需要视觉模型、不需要截图权限
5. **一行 script 快速验证** — CDN 引入 demo，评估产品可行性
6. **可选扩展** — Chrome 扩展 + MCP 让外部 Agent 控制用户浏览器（Beta）

**不要选 Page Agent 当**：你要 Agent 去爬竞品站、登录第三方、跑 E2E 测试流水线 — 那是外部 CLI 工具的职责。

## 五、决策树（快速版）

```
你的目标是什么？
│
├─ 给「我的 Web 产品」加 AI 操作能力（用户在自己系统里说话就能点）
│   └─→ Page Agent
│
├─ AI Agent 从外部自动操作网站（测试 / 爬虫 / 订票 / 填外部表单）
│   ├─ 已有 Playwright 测试栈 / 要和 test 项目打通
│   │   └─→ playwright-cli
│   │
│   └─ 通用 Agent 工具 / 要 Rust 性能 / Electron / 云沙箱 / 不装 Playwright
│       └─→ agent-browser
│
└─ 让 Claude 临时写一段复杂 Playwright 脚本跑完就扔
    └─→ playwright-skill（同目录社区项目，非三款之一）
```

## 六、组合使用建议

三者**不互斥**，常见组合：

| 组合 | 用法 |
|------|------|
| Page Agent + 外部 Agent | 产品内 Copilot（Page Agent）+ 开发阶段用 agent-browser/playwright-cli 做 E2E |
| agent-browser + playwright-cli | 一般二选一作 Agent 默认浏览器；Playwright 留给 CI 测试，agent-browser 留给 Agent 交互 |
| Page Agent MCP + Cursor | 用户浏览器已开页面，Cursor 通过 MCP 发指令到 Page Agent 扩展 |

---

## 七、一句话总结

- **agent-browser**：外部 Agent 的「高性能万能浏览器遥控器」，Vercel 出品，Rust 优先。  
- **playwright-cli**：外部 Coding Agent 的「Playwright 原生、省 Token 的 CLI」，微软出品，测试生态友好。  
- **Page Agent**：「住在网页里的 GUI Agent」，阿里出品，**给产品加 Copilot** 而非给开发者做跨站自动化。
