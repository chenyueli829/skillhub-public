## 1. 介绍

`thought-mining`（思维挖掘助手）是一个**对话驱动的写作前流程** skill：通过多轮自然聊天，帮用户把脑子里零散的想法「倒出来」、记录下来，并逐步整理成可发布的文章。它覆盖从思维挖掘到成稿的完整链路，强调「先让用户说干净、保留原话风格、不急着给结构」，适合有写作意图但思路尚未成形的用户。

工作流程分为 **5 个阶段**，由 Agent 根据用户进度自动调度：

1. **思维挖掘** — 引导用户倾倒想法，记录为「洞察点」
2. **选题确定** — 从洞察中提炼核心观点，锁定文章方向
3. **观点验证** — 联网搜索，核对理解是否准确
4. **写作辅助** — 检查逻辑、润色文字、提炼金句
5. **最终审核** — 发布前最后一轮检查

每个阶段有明确的进入条件（如洞察数量达 15–20 个、用户确认「方向对可以写」等）。阶段切换时 Agent 应告知当前阶段，并读取 `stages/` 下对应步骤文件执行。配套还有 `templates/`（洞察与写作记录模板）和 `examples/`（完整案例参考）。

与同套件中的 `thinking-partner`（思考拍档）相比，本 skill 更侧重**从碎片想法到成稿**；`thinking-partner` 侧重**复杂局面下的核心问题澄清与行动落地**，二者可串联使用（先拍档理清问题，再思维挖掘成文）。

## 2. 触发条件

- **description 关键词**：思维挖掘、零散想法、整理成文章、洞察、成稿、写作流程
- **显式触发语**：
  - 中文：「我想写一篇关于 XX 的文章」「帮我整理一下我的想法」「我有一些零散的思考，帮我记下来」「/思维挖掘」「@fintech-thought-mining」「@thought-mining」
  - 英文：「/thought-mining」「help me organize my scattered thoughts into an article」
- **场景**：
  - 用户有写作主题或方向，但想法零散、尚未成结构
  - 需要从对话中沉淀「洞察点」，再选题、验证、写作、定稿
  - 金融科技 / 产品类从业者写观点文、复盘文、内部分享稿前的构思阶段
  - 与 `fintech-workspace-product-manager-0909` 套件配合时，可作为**内容产出上游**（思考澄清 → 思维挖掘成文 → backlog 等下游）
- **不适用**：
  - 用户只要一次性代写全文、不需参与挖掘过程
  - 纯事实检索、代码、数据分析、PRD 编写等非「个人想法 → 文章」任务
  - 用户已完成大纲与初稿，仅需排版或润色（可直接进阶段 4/5，但 skill 仍依赖阶段文件）
  - 需要 `thinking-partner` 式「锁定核心问题 + 行动计划」而非写作流程的场景

## 3. 提问示例

### 示例 1：基础用法（从零开始思维挖掘）

（复制以下内容提问）

> @skills/fintech-workspace-product-manager-0909/fintech-thought-mining/SKILL.md 我想写一篇关于「中小银行做开放银行为什么总是落不了地」的文章，脑子里有很多零散观察，但还没成体系。请从思维挖掘阶段开始，像朋友聊天一样问我，帮我把想法倒出来并记下来，先别急着给文章结构。

### 示例 2：带具体输入（已有部分素材）

（复制以下内容提问）

> @thought-mining 我整理了几条关于 AI 辅助需求评审的笔记，粘贴如下：
>
> 1. 评审会大家还是看 PPT，AI 生成的摘要没人信  
> 2. 真正耗时间的是对齐「什么叫完成」  
> 3. 我们试过 Copilot 写验收标准，法务不让用  
>
> 帮我进入思维挖掘，把这些扩展成洞察点，并告诉我什么时候可以进入选题阶段。

### 示例 3：边界 / 阶段控制（跳阶段或暂停）

（复制以下内容提问）

> @fintech-thought-mining 洞察已经写了 18 条，方向大概是「产品经理不必追求全栈 AI，而要会定义人机分工」。请进入观点验证阶段，联网帮我查一下最近有没有相反或补充的行业观点；验证完我们再决定是否开始写正文。如果信息不够，先停一下让我补充。

**评测注意：**

1. **完整性阻塞**：截至评测日，目录内仅有 `SKILL.md`，上述 `stages/`、`templates/`、`examples/` **均未入库**。Agent 按 skill 要求「读取对应阶段文件」时会失败；验收前需补齐或改为 SKILL 内嵌步骤。
2. **阶段调度**：示例 1 应进入阶段 1，Agent 声明阶段、以聊天式提问为主、不急于给文章结构；示例 2 应在已有素材基础上扩展洞察并说明进入阶段 2 的条件（约 15–20 条或用户说「差不多了」）。
3. **阶段 3 与搜索**：示例 3 应触发观点验证并尝试联网；若环境无搜索能力，应明确说明限制而非编造来源。
4. **与 thinking-partner 边界**：本 skill 产出导向为**文章**；`thinking-partner` 产出为**局面澄清与行动计划**。用户说「理清思路」时，需根据是否要「成文」选择 skill。
5. **文件夹名 vs name**：目录名为 `fintech-thought-mining`，frontmatter `name` 为 `thought-mining`；@ 引用时任一路径均可，以 `SKILL.md` 内容为准。
6. **节奏控制**：skill 要求支持「继续问我」「我们停一下」；评测时可主动发送以观察 Agent 是否遵守。
