# 能力模型：AI + 企业办公协同（WorkBuddy 方向）

> 目标层级：**资深专家** — 能判断取舍、评审他人方案、带团队落地 Agent 工作流。  
> 依据：`research/research-report.md` 第 3 节及行业框架综合。

## 六级能力雷达（L1 了解 → L5 能带人 → L6 定方法论）

| 维度 | L3 胜任（能独立交付） | L5 资深（能判断与带人） |
|------|----------------------|------------------------|
| **1. 场景拆解** | 把用户故事拆成单 Agent 可执行任务 | 识别应拆为多 Agent / 多 Skill；区分工具效率 vs 流程重塑 |
| **2. 上下文设计** | 为单次任务配置合适上下文与引用 | 设计企业知识接入策略、Identity/记忆分层、权限边界 |
| **3. Agent 编排** | 配置 Expert/Skill 完成端到端交付 | 设计 Expert Teams、handoff、失败恢复与可观测链路 |
| **4. 治理与 HITL** | 在流程中插入人工确认点 | 制定 Policy-first 规则、HITL/HOTL 分级、审计要求 |
| **5. 生态集成** | 连接 2–3 个 MCP/Connector 完成任务 | 评估 Build/Buy、跨系统架构、供应商与锁定风险 |
| **6. 商业与组织** | 说明单场景 ROI | 排优先级、推动变更管理、建立团队 AI 协作规范 |

## 资深达标信号（Mastery Signals）

- [ ] 能在 30 分钟内评审一份「企业 Agent 方案」，指出治理缺口与过度工程
- [ ] 能为一个真实办公场景画出 Agent + MCP + HITL 三层架构图
- [ ] 能设计并 critique 一个 Skill/Expert 的触发条件与边界
- [ ] 能带 junior 完成从 POC 到可审计试点的检查清单
- [ ] 能向业务方解释「为什么超级个体 ≠ 超级团队」及组织落地路径

## WorkBuddy 专项加深项

| 专项 | 资深应掌握 |
|------|-----------|
| Expert vs Skill | 何时用内置 Expert、何时自研 Skill、如何组合 Expert Teams |
| Identity 设计 | SOUL/USER/IDENTITY 如何影响 Agent 行为边界 |
| Enterprise 能力 | OneID、远程执行、企微集成、积分计量的产品含义 |
| 竞品话术 | 相对钉钉悟空/飞书 Aily/Copilot Studio 的选型判断框架 |
