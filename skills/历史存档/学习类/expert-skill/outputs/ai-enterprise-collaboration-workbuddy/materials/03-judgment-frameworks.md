# 03 判断框架：取舍与架构决策

## 框架 1：场景分级矩阵（决定 HITL 与编排深度）

|  | 低风险 | 高风险 |
|--|--------|--------|
| **高频率** | HOTL + 模板化 Skill | HITL + 审计 + 限权 MCP |
| **低频率** | 单 Expert 即可 | Expert Team + 强制人审 |

**操作**：先定风险（数据敏感度、对外性、不可逆性），再定频率。

## 框架 2：Build / Buy / Configure

| 路径 | 何时选 | WorkBuddy 映射 |
|------|--------|----------------|
| **Configure** | 内置 Expert/Skill 覆盖 80% | 直接用 + 微调提示 |
| **Buy** | 需要企业治理、快速上线 | WorkBuddy Enterprise |
| **Build** | 独特 IP、强合规定制 | 自研 Skill + MCP Server |

## 框架 3：三层栈检查单

部署任何企业 Agent 方案前过一遍：

- [ ] **推理层**：任务分解是否可解释？失败如何恢复？
- [ ] **连接层**：MCP 权限最小化？工具暴露是否可审计？
- [ ] **治理层**：谁批准？谁担责？日志保留多久？

## 框架 4：AI 成熟度阶梯（选型话术）

| Level | 特征 | 产品策略 |
|-------|------|----------|
| L1 | 个人效率工具 | Copilot 类、内置助手 |
| L2 | 流程嵌入 | 审批流 + Agent 节点 |
| L3 | 自主 Agent + 组织知识 | WorkBuddy Enterprise、悟空、Aily 深度 |

**资深话术**：「你们现在主要在 L__，这个方案只能支撑到 L__，要到 L__ 还缺 __。」

## 框架 5：Skill 设计五问

设计或评审一个 Skill 时：

1. **触发边界**：什么情况下不该触发？
2. **输入契约**：用户必须提供什么？
3. **输出契约**：交付物格式与保存位置？
4. **外部依赖**：MCP/API/凭证？
5. **停止条件**：什么情况下必须停并请人介入？

## 框架 6：竞品快速对比（1 分钟版）

问三个问题：
1. 主 Job 在谁家生态里闭环？
2. 跨系统执行谁更强？
3. 治理开箱程度？

→ 对齐 research-report §1.2 表格作答。
