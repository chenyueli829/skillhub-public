# 一个产品经理的 AI Native 实战：从小白到「养虾大户」

> 半年前我连一句 prompt 都写不利索，现在我让 AI 帮我当产品、运营、架构师。
> 这篇文章不讲概念，只讲我踩过的坑和留下的真东西——以及 3 个你今天就能抄走的干货。

---

## 一、2026，是 Agent 爆发的元年

如果说前两年大家还在讨论「大模型能不能用」，那么 2026 这一年，话题已经彻底变成了「Agent 怎么帮我把活干完」。

我自己的这半年，几乎就是一部「养虾历程」——工具一路换，本质是认知一路升：

| 阶段 | 我用了什么 | 当时在解决什么 |
|---|---|---|
| 阶段一 | Openclaw（内网）· Lighthouse · 飞书养虾 | 第一次让 AI 真正干活，跑通流程 |
| 阶段二 | 内网 Hermes · 本地 Hermes | 把能力搬到手边，提速 |
| 阶段三 | Workbuddy · Claude Code 类 AI 办公工具崛起 | 多 Agent 协作，进入「军团」模式 |

再叠加上知识库、Skill 这些新的「能力沉淀方式」，我的体感很清楚：

- 阶段一是「哇，居然能跑通」；
- 阶段二是「快了，但还是单线作战」；
- 阶段三是「一个人，开始能指挥一支队伍」。

**换工具是表象，真正变的是我把任务拆成流程的能力。**

## 二、作为产品经理，我做了哪些事？

这半年，我主要做了两件事。

**第一件，是给自己造分身、拓展技能。**

- **Lylian 的产品军团**：产品、运营、架构师，各司其职——这不是比喻，是真的有对应的 Agent 在干活。
- **Skill 评测**：用过很多 Skill，我开始系统地评测它们——哪些夯、哪些拉。
- **构建个人知识库**：把零散的认知沉淀下来，让 AI 能随时调用。
- **金融资金业务产品助理**：正在培养中的一个「兵」，目标 Q3 自己用，Q4 能对外接客。

**第二件，是在 AI 原生的新项目里小团队快跑。**

打法很简单：**想法 → Demo → 落地**。比如支付场景下的 Agent2Agent 探索，就是从一个想法快速推进到 Demo 的完整链路。

这里我最想强调的一点是：AI Native 能力，不是「我会用哪些工具」，而是 **「我能不能定义 AI 的输入、输出和判断标准」**。

## 三、我的分身 + 技能 + 知识库

### 1. 关于 Skill：哪些夯、哪些拉？

先澄清一个误区：**很多人以为 Skill 就是 prompt 合集，其实不是。**

> Skill = 给 AI 写的 SOP（标准作业程序），不是一次性对话。

| 维度 | 普通 Prompt | Skill |
|---|---|---|
| 形态 | 一次性对话 | 持久化的 SKILL.md 文件 |
| 触发 | 每次手动粘贴 | 自动匹配 / @ 显式调用 |
| 内容 | 几句话 | 完整工作流 + 脚本 + 参考文档 |
| 复用 | 难，每次重写 | 一键安装、反复调用 |

一句话：**Prompt 是你说一次，Skill 是你定一次规矩，AI 以后都照着办。**

那么按场景，我用下来哪些工具/Skill 真正活了下来？

- **行业调研**：DeepSearch（多维度、多角度）· Codebuddy（深度研究）。
- **产品设计**：Claude Design（统一 IP 风格）· Figma Make · Lovable（快速出好看的 Demo）。
- **爬虫 / 信息采集**：YouTube · NotebookLM · 小宇宙。
- **网页模拟用户**：Marvis · Agent-Browser（跑用户反馈、做痛点总结）。
- **写 PPT**：NotebookLM · Frontend-Slides。

而我评判一个 Skill 「夯」还是「拉」的标准，送给你：

- **夯**：输出稳定、有数据结构、能复用、有质量红线。
- **拉**：每次结果飘、靠运气、没有质量红线、会编数据。

**会选 Skill，比会写 Prompt 更重要。**

### 2. 关于知识库：Obsidian + Agent + Sync

我的知识库架构一句话就能说清：**本地 Obsidian 沉淀 + Agent 调用 + 多端 Sync。**

它的价值不在于「存了多少」，而在于**「能不能被 AI 随时调用」**。最近我也在尝试做一个线下场景的知识库，不过被我的「虾」（Agent）打了个不高的分——这恰恰说明，**让 AI 当评审，能帮你把一些拍脑袋的想法及时按住。**

> 知识库不是仓库，是 AI 的外挂大脑——存了能用，才是真存了。

## 四、如何学习，如何保持跟进？

信息焦虑的解法，不是更努力地刷，而是**让信息自己流到你面前**。

我的三件套是：

- **Follow Builders / AIHot**：信息流式被动接收，跟住一线在造东西的人。
- **听播客**：创业者视角的一手思考（比如 MiniMax、智谱这类团队的分享）。
- **关注头部大 V**（张咋啦、baoyu 等）：相当于有人帮你做了一轮预筛选。

**干货①：不用翻墙就能用的 AI 从业者资讯源。**

- 自动聚合 **26 位全球从业者的 Twitter 动态**，不用翻墙也能跟进；
- AI 相关播客 / 资讯自动推送，从业者视角的一手内容。

**保持跟进不靠刷，靠让信息自己流到你面前。**

## 五、案例：ProductLab 产品决策实验室

如果要选一个最能代表我这半年的项目，那就是 **ProductLab**。

**痛点**：早期做产品，缺的从来不是想法，而是判断——

- 这个需求是真痛点，还是我自己的想象？
- 用户现在用什么替代方案？
- 竞品已经做到什么程度？
- 最大风险是什么，下一步应该验证什么？

传统做法是反复打开搜索、社区、竞品官网——看了很多，却不知道下一步做什么。

**做了什么**：我把整条产品研究链路压成了一套工具 + Skill：

> 领域情报 → 机会雷达 → 竞品分析 → 反馈雷达 → 产品判断台

每个环节都沉淀成了可复用的 Skill（product-judgment / product-radar / competitor-intel / domain-intel 等）。

**核心创新——判断卡**：它不写长报告、不打 100 分，而是固定输出：

- **3 个关键假设**
- **1 个最大风险**
- **1–3 个低成本验证动作**

为什么要故意限制输出？因为 **AI 很容易生成很长的报告，但早期产品探索真正需要的不是长，而是清楚。**

这个项目让我对 AI Native 有了更深的理解，可以浓缩成四点：

1. **把 AI 当流程引擎，不是文本助手**——它参与检索 → 归纳 → 结构化 → 生成 → 提炼的完整工作流。
2. **能把模糊问题压缩成可判断结构**——强制收敛到：目标用户是谁、痛点是否真实、获客是否可行。
3. **有证据分级意识**——竞品证据 / 用户反馈 / 趋势信号 / 待验证假设，缺证据就标「待验证」，绝不伪装确定性。
4. **把一次性产出沉淀成可复用 Skill**——标准模板 + 固定数据结构 + 触发语义 + 质量红线 + 验证清单。

## 六、产品经理到底用 AI 做什么？

把前面所有故事抽象成一张「能力地图」：

| 能力维度 | AI 具体在做什么 |
|---|---|
| 提认知 | 市场研究 · 竞品分析 · 行业趋势 |
| 做判断 | 正方 / 反方、多维度思考（→ ProductLab 判断卡） |
| 去行动 | 用户调研 · 机会洞察 · PRD · Vibe Coding · 设计 |
| 找合作 | 架构师 Agent |
| 做运营 | 自动化运营 |
| 懂用户 | 模拟小白用户（Agent-Browser 跑用户反馈） |

**不是每个维度都要自己干，但每个维度你都要能定义 AI 怎么干。**

## 七、产品预告 & 收束

ProductLab 接下来会往三个方向迭代：

1. **判断台产品化**：从工具集合收敛成一个主体验，输入想法直接得到判断卡。
2. **真实数据源接入**：搜索、社区、GitHub、Product Hunt、小红书的实时数据。
3. **判断卡传播机制**：截图、Markdown 复制、投稿案例页——把判断卡变成可传播的资产。

最后，三句话送给你：

1. 换工具是表象，**升认知才是本质**。
2. 一个人，可以靠 AI **扩展成一个团队**。
3. **把经验写成 Skill，让 AI 替你重复执行。**
