## 5. 干货② SkillHub Public 精选库 + Skill 评测法（7 min）

> 重头干货。这一段有两个交付物：一是概念认知（什么是 Skill），二是实物（精选库仓库）。节奏先慢后快。

### 5.1 什么是 Skill（1.5 min）

> 概念澄清。很多人以为 Skill 就是 prompt 合集，不是。

- **Skill = 给 AI 写的 SOP（标准作业程序）**，不是一次性对话。
- Prompt vs Skill 对比：

| 维度 | 普通 Prompt | Skill |
|---|---|---|
| 形态 | 一次性对话 | 持久化 SKILL.md 文件 |
| 触发 | 每次手动粘贴 | 自动匹配 / @ 显式调用 |
| 内容 | 几句话 | 完整工作流 + 脚本 + 参考文档 |
| 复用 | 难，每次重写 | GitHub 链接一键安装 |

- 一句话：**「Prompt 是你说一次，Skill 是你定一次规矩，AI 以后都照着办。」**

### 5.2 为什么要做 SkillHub Public（1 min）

> 三个痛点，快速过。

- **散落**：GitHub、大 V 分享、官方仓库——找起来费时。
- **质量参差**：有的缺中文，有的根本没跑通过。
- **安装门槛**：不同 Agent 路径不同，容易装错。
- 定位一句话：**精选 + 归档 + 验证——我筛过、用过、愿意推荐的清单。**

### 5.3 仓库概况 & 结构（1 min）

> 数字快念 + 来源分类。

- **规模**：200+ Skill 入口 → 63 个 A 精选 → 10+ 场景分类 → 7 个来源合集。
- **仓库结构**：
  - A 精选 10 个 Skill（按场景：PRD、研究、写作、绘图、PPT、设计）
  - baoyu 同款 · 22 个（公众号、小红书、漫画、信息图全流程）
  - Hermes 官方 · 71 个（开发、创意、研究、生产力、MLOps）
  - 卡兹克 · 三万 · Anthropic（大 V 实战 + 官方标准 + 历史存档）

### 5.4 按场景评测：哪些夯、哪些拉（2 min）

> 节奏提示：加快，清单式快念。每个场景一句话点评。

- **行业调研**：DeepSearch（多维多角度）· Codebuddy（深度研究）。
- **产品设计**：Claude Design · Figma Make · Lovable（快速出 Demo）。
- **爬虫 / 信息**：YouTube · NotebookLM · 小宇宙。
- **网页模拟用户**：Marvis · Agent-Browser（跑用户反馈、痛点总结）。
- **写 PPT**：NotebookLM · Frontend-Slides。
- **评测判断框架**（送给听众）：
  - **夯**：输出稳定、有数据结构、能复用、有质量红线。
  - **拉**：每次结果飘、靠运气、无质量红线、编数据。

### 5.5 使用哲学 + 入门三件套（1.5 min）

> 收束这段，给出可执行的行动建议。

- **三条哲学**：
  1. Skill 是 SOP，不是万能 Prompt——要有硬约束。
  2. 只装真正会用的——上下文是稀缺资源。
  3. 先评测再入库——补齐中文 + 评测文档。
- **入门三件套**（按角色推荐）：

| 角色 | 推荐组合 |
|---|---|
| 产品经理 | brainstorming + idea-validator + claim-verifier |
| 内容创作者 | baoyu-post-to-wechat + humanizer + baoyu-comic |
| 开发者 | brainstorming + writing-plans + systematic-debugging |
| 研究者 | ecc-deep-research + last30days + hv-analysis |

- 仓库地址：`github.com/chenyueli829/skillhub-public`
- 一句话：**「会选 Skill，比会写 Prompt 更重要。」**

## 7. 案例重头戏：ProductLab 产品决策实验室（6 min）

> 全场高潮。先讲痛点，再讲做法，最后讲「判断卡」这个核心创新。这段放慢，金句密集。

### 7.1 痛点（1 min）

- 早期做产品不缺想法，缺判断：
  - 这个需求是真痛点，还是我自己的想象？
  - 用户现在用什么替代方案？
  - 竞品已经做到什么程度？
  - 最大风险是什么，下一步应该验证什么？
- 一句话：**「传统做法是反复打开搜索、社区、竞品官网——看了很多，但不知道下一步做什么。」**

### 7.2 做了什么（1.5 min）

> 展示完整链路。

- 把产品研究链路压成一套工具 + Skill：
  - **领域情报** → **机会雷达** → **竞品分析** → **反馈雷达** → **产品判断台**
- 闭环逻辑：领域认知 → 机会发现 → 竞品拆解 → 用户反馈 → 产品判断 → 判断卡传播。
- 每个环节都沉淀成了可复用 Skill（product-judgment / product-radar / competitor-intel / domain-intel 等）。

### 7.3 核心创新：判断卡（1.5 min）

> 现场展示 Demo。

- 不写长报告、不打 100 分。
- 固定输出：**3 个关键假设 + 1 个最大风险 + 1–3 个低成本验证动作**。
- 故意限制输出的原因：**AI 容易生成很长的报告，但早期产品探索真正需要的不是长，而是清楚。**

### 7.4 AI Native 的四个体现（1.5 min）

> 金句密集区，每条展开一句。

1. **把 AI 当流程引擎，不是文本助手**——AI 参与完整工作流：检索 → 归纳 → 结构化 → 生成 → 提炼。
2. **能把模糊问题压缩成可判断结构**——强制收敛到：目标用户是谁？痛点是否真实？获客是否可行？
3. **有证据分级意识**——竞品证据 / 用户反馈 / 趋势信号 / 样例数据 / 待验证假设，缺证据就标「待验证」，不伪装确定性。
4. **把一次性产出沉淀成可复用 Skill**——标准模板 + 固定数据结构 + 触发语义 + 质量红线 + 验证清单。

### 7.5 三条经验（0.5 min）

> 快收，送给听众。

1. AI Native 的关键不是「生成更多」，而是**「压缩更准」**。
2. 好的 AI 工具需要明确**质量红线**（不编数据、不把样例当事实、不给伪建议）。
3. **个人能力可以通过 Skill 变成系统能力**——过去能力在脑子里，现在可以封装成 AI 重复执行的方法。

  1. **判断台产品化**：从工具集合收敛成一个主体验，输入想法直接得到判断卡。
