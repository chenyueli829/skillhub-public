# Skill 评测准备

对**目标 skill** 执行评测前标准化准备，产出中文可读版本与评测摘要文档。所有产出文件写入**目标 skill 所在目录**（与 `SKILL.md` 同级）。

## 何时使用

- 用户 @ 本 skill 并要求评测某个 skill
- 用户说「Skill 评测」「评测 skill」「生成 Eval」「准备验收」
- 入库新 skill 前需要补齐中文翻译与评测摘要

## 输入

用户需指明目标 skill，以下任一即可：

- skill 文件夹路径（如 `skills/验收类/claim-verifier`）
- `@` 引用 skill 目录或 `SKILL.md`
- 仓库内 skill 的 `name`（frontmatter）或文件夹名

若未指明，先询问目标 skill，**不得**猜测。

## 执行流程

按顺序完成，并在回复中汇报每步结果。

### 第 1 步：定位并阅读 SKILL.md

1. 在目标目录找到主入口文件，优先级：`SKILL.md` > `SKILL.zh-CN.md` > 其它 `SKILL*.md`
2. 通读全文，并扫描同目录下的 `scripts/`、`reference.md`、`README*` 等辅助文件（用于第 3 步依赖提取）
3. 记录 frontmatter 中的 `name`、`description`

### 第 2 步：翻译（条件执行）

**判断语言**：以 `SKILL.md` 正文为主。若标题、章节、说明性段落以英文为主，视为英文 skill。

| 情况 | 动作 |
|------|------|
| 英文，且不存在 `SKILL-zh.md` | 新建 `SKILL-zh.md`，完整翻译 `SKILL.md`（保留 frontmatter 结构，`name` 可不变，`description` 译成中文） |
| 英文，已存在 `SKILL-zh.md` | 对比 `SKILL.md` 是否有实质更新；有则更新 `SKILL-zh.md`，无则跳过并说明 |
| 已是中文，或已有 `SKILL-zh.md` / `SKILL.zh-CN.md` 且与 `SKILL.md` 等价 | 跳过翻译，说明原因 |

**翻译要求**：

- 保留 Markdown 结构、表格、代码块、链接路径
- 技术术语可保留英文并附中文（如 claims → 主张）
- 不删改原 skill 的执行逻辑与约束

### 第 3 步：生成 Eval 文档

在目标 skill 目录新建：

```
技能评测-{技能名称}-{YYYYMMDD}.md
```

- **技能名称**：优先用 frontmatter `name`；若无则用文件夹名（kebab-case，不含版本号后缀如 `-1.0.0`）
- **日期**：执行当日本地日期，格式 `YYYYMMDD`（例：`20260615`）
- 同日重复执行时，在文件名后加 `-2`、`-3`…，或覆盖前询问用户（默认追加序号避免覆盖）

**文档结构**（必须包含以下四节）：

```markdown
# 技能评测：{技能名称}

> 生成日期：YYYY-MM-DD  
> 入口文件：{相对路径/SKILL.md}  
> 版本：{frontmatter version 或「未标注」}

## 1. 介绍

（2–5 段中文摘要：这个 skill 做什么、解决什么问题、主要输出是什么。综合 description、Overview/概述、执行步骤提炼，避免照抄全文。）

## 2. 触发条件

（Agent 应在何时自动或应用户要求启用该 skill。）

- **description 关键词**：…
- **显式触发语**：用户可能说的话（中英文）
- **场景**：…
- **不适用**：…

## 3. 提问示例

（供评测者**直接复制**到对话中使用的示例提问，**至少 3 条**。）

每条示例须：

- 写成完整、可独立发送的用户消息（可含 `@技能目录` 或 `@SKILL.md`）
- 覆盖不同典型场景（如：基础用法、带具体输入、边界/可选能力）
- 贴近该 skill 的真实输入格式（粘贴文章、文件路径、参数等）

格式：

```
### 示例 1：{场景简述}

（复制以下内容提问）

> …

### 示例 2：{场景简述}

（复制以下内容提问）

> …

### 示例 3：{场景简述}

（复制以下内容提问）

> …
```

## 4. 外部依赖

（运行该 skill 时，skill 文件夹**之外**或**环境级**的依赖。无则写「无」并简要说明。）

### API / 在线服务

| 服务 | 用途 | 是否必需 | 备注 |
|------|------|----------|------|
| … | … | 是/否 | … |

### MCP / CLI / 系统能力

| 依赖 | 用途 | 是否必需 |
|------|------|----------|
| … | … | … |

### 环境变量 / 凭证

| 变量名 | 用途 |
|--------|------|
| … | … |

### skill 目录外的路径

| 路径 | 用途 |
|------|------|
| … | … |

### 第三方包 / 运行时

（pip/npm/系统包等，若 skill 明确要求安装）

- …
```

**依赖提取检查清单**（逐项检索 SKILL 全文及同目录脚本）：

- HTTP/API 端点、域名、SaaS 产品名
- MCP server 名称、`CallMcpTool` 相关说明
- `~/.cursor`、`~/.config`、绝对路径、其它仓库路径
- 环境变量、API Key、Token、OAuth
- 浏览器自动化、数据库、云部署平台
- `scripts/` 中的 `import`、`curl`、`fetch` 目标

## 完成汇报

向用户简要说明：

1. 目标 skill 路径
2. 是否新建/更新 `SKILL-zh.md`
3. `技能评测-{技能名称}-*.md` 文件路径
4. Eval 中「提问示例」条数是否 ≥ 3
5. 外部依赖中需人工准备的关键项（凭证、MCP、内网服务等）

## 约束

- **仅修改目标 skill 目录**内的文件；不改动其它 skill
- 不执行目标 skill 的业务逻辑（本流程只做阅读、翻译、摘要）
- 翻译与 Eval 内容须基于实际文件，**禁止编造**不存在的 API 或路径
- 若 `SKILL.md` 缺失或目录不是合法 skill，停止并报错

## 示例

**输入**：评测 `skills/验收类/claim-verifier`

**产出**：

- `skills/验收类/claim-verifier/SKILL-zh.md`（若原为英文且尚无中文版）
- `skills/验收类/claim-verifier/技能评测-claim-verifier-20260615.md`
